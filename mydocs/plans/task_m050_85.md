# 프로젝트 기억 중심 README 소개 개편 및 다국어 동기화 수행계획서

GitHub Issue: [#85](https://github.com/postmelee/hyper-waterfall/issues/85)
마일스톤: M050

## 목적

Hyper-Waterfall의 대표 소개를 승인 중심 설명에서 작업 맥락 증류와 지속되는 프로젝트 기억 중심 설명으로 재정렬한다. 작업지시자가 제공한 영문 README 초안을 최대한 유지하되, 문서만으로 모든 맥락이 완전히 복원된다고 단정하는 표현과 실제 규칙보다 강한 표현을 조정하고 기존 운영 사실을 보존한다.

영문 최종안을 기준으로 한국어와 중국어 README를 같은 메시지와 주요 구조로 동기화하여 언어에 따라 프로젝트 정체성이 달라 보이지 않게 한다.

## 배경

현재 README 상단은 `AI pair programming`, 추적 가능성, 승인 가능성을 가장 먼저 소개한다. 승인 게이트는 Hyper-Waterfall의 중요한 운영 메커니즘이지만, Codex를 포함한 일반 AI 코딩 도구도 실행 전 승인을 요청하므로 대표 차별점으로는 충분하지 않다.

프로젝트의 문서 구조는 일시적인 세션 맥락에서 의도, 범위, 계획, 결정, 구현 진행, 검증 근거를 구조화된 산출물로 남기고 다음 세션·에이전트·기여자가 이를 작업 맥락으로 재사용하도록 설계되어 있다. Issue #85와 작업지시자가 제공한 `README(1).md` 초안은 이 특성을 `context distillation`, `persistent project memory`, `human-governed AI coding workflow`로 설명한다.

사전 비교 결과 초안은 핵심 포지셔닝이 현재 README보다 우수하고 기존 명령·경로·절차도 대체로 보존한다. 다만 전체 492줄을 다시 쓰는 편집본이므로, 초안을 최대한 유지하면서도 불필요한 문체 변경, 반복, 과도한 단정은 최종 검토가 필요하다.

## 범위

### 포함

- `README.md`를 제공된 초안 기반으로 개편하고 핵심 표현의 정확성·반복·운영 사실을 조정한다.
- `README.ko.md`를 영문 최종안의 메시지와 주요 섹션 구조에 맞게 한국어로 동기화한다.
- `README.zh-CN.md`를 영문 최종안의 메시지와 주요 섹션 구조에 맞게 중국어 간체로 동기화한다.
- 세 README의 설치 명령, 버전, 경로, Task 절차, SKILL 목록, 배포 정책, 실제 사례를 보존한다.
- 세 README의 Markdown 구조, 상대 링크, 목차 앵커, 핵심 용어 대응을 검증한다.
- 근거가 약한 정량·절대 표현을 제거하거나 방어 가능한 표현으로 조정한다.

### 제외

- Hyper-Waterfall 운영 규칙, 승인 절차, SKILL 호출 시점 또는 출력 계약 변경
- `templates/`, `mydocs/manual/`, `mydocs/skills/` 내용 변경
- CLI, manifest, lifecycle, locale pack 구조 또는 배포 버전 변경
- 작업지시자가 제공한 `/Users/melee/Downloads/README(1).md` 원본 수정

## 설계 방향

- 영문은 제공된 초안의 구성과 문장을 기본으로 삼고, 사전 검토에서 확인한 정확성 문제만 제한적으로 보정한다.
- 대표 설명은 `human-governed AI coding workflow that distills ephemeral session context into persistent project memory`를 중심으로 한다.
- `approval-driven`은 대표 가치가 아니라 human governance를 구현하는 decision gate로 설명한다.
- `AI pair programming`은 문맥상 원 방법론 인용이 필요한 경우를 제외하고 `AI coding workflow` 또는 `AI coding agent`로 전환한다.
- 문서 산출물이 다음 작업에 필요한 핵심 맥락을 제공한다는 효용은 강조하되, 모든 맥락의 완전한 복원을 보장하지 않는다. `reconstruct the work` 같은 강한 표현은 `recover the essential context` 또는 `continue from a documented baseline`로 조정한다.
- `1 Issue = 1 Task = 1 Branch = 1 Session`은 강제 불변식이 아니라 권장 운영 모델로 표현한다.
- `persistent project memory`는 상단과 핵심 설명에서 일관되게 사용하되, 후반에서는 `shared context`, `documented baseline`, `handoff context`, `durable work history`를 문맥에 맞게 사용해 반복을 줄인다.
- 한국어와 중국어는 영문 문장을 기계적으로 직역하지 않고 의미, 용어, 섹션 대응을 보존하는 현지화를 적용한다.
- 기존 README의 기능적 사실과 초안에서 보존된 상세 절차는 변경하지 않는다.

## 잠정 단계

- **Stage 1 — 영문 README 포지셔닝 개편**
  - 제공된 초안을 `README.md`에 반영하고 정확성, 반복, 운영 사실을 보정한다.
  - 현재 README 대비 명령·경로·절차 보존과 영문 Markdown 구조를 검증한다.
- **Stage 2 — 한국어 README 동기화**
  - 영문 최종안의 메시지와 주요 구조를 `README.ko.md`에 한국어로 현지화한다.
  - 영문과 한국어의 섹션, 핵심 용어, 기능적 사실 대응을 검증한다.
- **Stage 3 — 중국어 README 동기화 및 통합 검증**
  - 영문 최종안의 메시지와 주요 구조를 `README.zh-CN.md`에 중국어 간체로 현지화한다.
  - 세 README의 링크, 앵커, 명령, 경로, 버전, SKILL 목록과 테스트를 통합 검증한다.

  - `npm test`

### 통합 검증

- 기존 설치 명령, 버전, 경로, Task 절차, SKILL 목록, 배포 정책, 실제 사례가 보존된다.

## 리스크

- **초안의 광범위한 문체 변경**: 핵심 포지셔닝과 무관한 문장 변경이 리뷰를 어렵게 할 수 있다. 초안을 기본으로 사용하되 기능적 사실이 같은 순수 문체 변경은 필요성을 다시 확인한다.
- **과도한 기억 복원 주장**: 프로젝트 문서가 모든 세션 맥락을 완전히 재현한다고 오해할 수 있다. 핵심 맥락과 문서화된 기준선 복원으로 표현을 제한한다.
- **다국어 의미 불일치**: 현지화 과정에서 human governance와 project memory의 관계가 달라질 수 있다. 섹션별 의미 대응표와 핵심 용어 검색으로 검증한다.
- **운영 정보 손실**: 전체 README 편집 과정에서 명령, 버전, 링크, 절차가 누락될 수 있다. 현재 README와 초안, 최종본을 비교해 보존 여부를 확인한다.
- **핵심 용어 과잉 반복**: `project memory`가 마케팅 용어처럼 반복될 수 있다. 상단에서는 고정 용어를 사용하고 후반에서는 문맥에 맞는 대체 표현을 사용한다.
